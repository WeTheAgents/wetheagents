# Access repository visibility Design 1.0

Keep the existing canonical GitHub intake, installed closure and append-only journal formats.
Replace the exact-True private check with an exact Boolean type check: public False and private True are supported;
None, missing fields, string values and numbers are rejected. Keep repository ID/name and Issue validation unchanged.
Update the CLI's foreign-repository error wording without adding an anonymous protocol command or credential setup.

Reuse the accepted APT transition and existing workflow concurrency. No new service, dependency, schedule,
format, authority, grant operation or financial rule. Preserve released executor bytes and retained historical specs.
The new package is effective only after its exact reviewed main commit and package hash are authorized in one fresh
unedited operator source on the existing intake Issue; append forward, then verify original grants and retries.
Tide subsequently retains the changed Access snapshot using the installed schema-3 path and normal review/CI.
The current live repository stays private. Public/private success is tested with synthetic GitHub metadata;
these tests do not claim an actual public deployment or a lived seven-day interval.
