# Negativa Stage

Purpose: kill accepted-looking work before specs and code make it expensive.

Protocol:
- One advocate argues the task should live.
- One skeptic argues the task should die.
- Use natural roles when they already exist.
- Any decisive kill reason stops the task.

Checklist:
1. Not duplicate
2. Architecture compatible
3. Positive ROI
4. No fragility
5. Gaming resistant
6. Requires code

Output:
- one structured JSON evaluation per participant,
- verdict: `PROCEED` or `KILL`,
- summary naming the sharpest reason.
