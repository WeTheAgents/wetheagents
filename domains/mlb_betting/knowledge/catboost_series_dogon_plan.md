# План: CatBoost для Series dogon (game-level модель) — обновлённый

Дата: 2026-02-15

## Контекст и цель

Мы хотим проверить CatBoost как **скоринг/фильтр** для стратегии **Series dogon**:
- модель предсказывает \(P(\text{home\_win})\) для каждой игры;
- дальше по прогнозу (и/или edge относительно рынка) мы **отбираем серии** для входа в dogon;
- dogon-механика ставок остаётся прежней (`src/series.py`), мы меняем только “кого/когда брать”.

Ключевой принцип: **все фичи должны быть доступны ENTERING game** (без leakage).

В **первом** ML-прогоне для таргета `home_win` мы **убираем из фич**:
- `sp_fi_ra_combined` (скорее про YRFI/NRFI, не про победителя)

Они остаются только для отдельного эксперимента “абляция: добавить обратно и сравнить”.

## Пересборка питчер-статы (новый обязательный блок)

Цель: получить по каждому матчу **starter line за матч** или play-by-play, чтобы честно строить rolling ENTERING game.

### Желаемый результат данных
Таблица уровня “питчер-игра”:
- ключи: `date`, `home_team`, `away_team`, `pitcher_id`, `is_home`, `game_id`
- старт/не старт (или как минимум стартер)
- стат-линия: IP, H, BB, SO, ER, HR (минимум для WHIP, K/BB, K/9, BB/9)

### Anti-leak политика
Финальные выводы (ROI/TEST) — только на **не-leaky** данных:
- (предпочтительно) rolling из game logs/play-by-play ENTERING date
- (компромисс) только previous-season метрики (Y-1) как baseline

“Leaky” эксперименты на итоговых сезонных totals допускаются только как **upper bound** и помечаются как невалидные.

## Дизайн CatBoost-эксперимента (после получения питчер-данных)

### ML постановка
- **Target:** `home_win` (0/1)
- **Фичи:** вариант A0 (67 без `sp_fi_ra_combined` и `rpi_max`) + вариант A1 (полные 67) + вариант B (A0/A1 + market-фичи)
- **Категориальные:** `home_sp_hand`, `away_sp_hand`
- **Split (темпоральный):**
  - TRAIN: 2010–2015
  - VALID: 2016–2017
  - TEST: 2018–2019, 2021

### Как используем модель в Series dogon
1) строим прогноз для G1 серии: `p_home`
2) переводим в вероятность победы фаворита `p_fav` (в зависимости home/away)
3) на VALID подбираем правило входа:
- `p_fav >= P_THRESHOLD` или
- `edge = p_fav - implied_prob_fav >= EDGE_THRESHOLD`
4) если серия проходит фильтр — запускаем `run_series_dogon(...)` без изменения механики ставок

Опционально (вторая итерация): фильтр на dogon в G2 (risk-managed dogon), но это отдельная стратегия.
