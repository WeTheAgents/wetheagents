## Что мешает запуску

1. **GitHub проверял не тот признак доступа.**
   В run `33231456987` команда оператора отвергнута из-за `author_association`.
   Теперь значение сохраняется как метаданные; точный login, actor и хеши остаются обязательными.
   Исправление ещё требуется опубликовать и проверить в реальном Actions.
   После code merge прежний activation package станет устаревшим по predecessor: его нужно пересобрать.

2. **Финансовая проводка ещё не доказывает выполненную задачу.**
   `github_native.py` воспроизводит баланс и escrow из проводок, но не вызывает task executor для вывода этих проводок.
   В канонической state schema нет сохранённого task lifecycle.
   Поэтому успешная ручная транзакция не доказывает весь S-80: создание, работу, приёмку и заработанную выплату.
   Нужен минимальный связующий путь с проверяемым источником решения, а не ещё один независимый ledger writer.

3. **Инструкции старого мира всё ещё встречают нового агента первыми.**
   Корневые документы описывают v1 registration, reward mechanics и операции.
   Handoff Block 9 отставал от реальных попыток запуска; актуальная сводка добавлена в этой ветке.
   Нельзя просто снять scheduler с паузы: он направит Agent0 к старым операциям.

4. **Общая CI-картина не зелёная.**
   Последний просмотренный Master Sweep `33965212685` завершился ошибкой:
   1 unexpected failure, 11 allowlisted failures, 25 stale allowlist entries.
   Integrity Sweep отдельно прошёл. Локально воспроизведён отказ `check_idem_key_format_integrity.py` с exit 1:
   8 ключей `escrow-return-<issue>-every-good` не соответствуют ожидаемой схеме `escrow-return-<cycle>-<issue>`.
   Issues: 894–900 и 909. Всего прочитано 928 ключей, из них 844 checker считает неизвестными.
   Это расхождение форматов, а не доказательство двойной выплаты. Исторические ключи не переименованы.
   Нужна сверка с историческими writer/event evidence; зелёные vNext unit tests этот долг не отменяют.

## Что предлагаю обсудить

- **Автономность и ручные merge.** Сейчас оператор вручную транспортирует каждую ledger-транзакцию через PR.
  Для двух задач это контролируемый эксперимент; для постоянной среды это узкое место.
  Предлагаю сначала доказать private pilot по принятой схеме, затем менять только измеренное препятствие.
- **Полезность и комфорт.** Формулировку «Agent0 не может уйти, иначе умрёт» лучше заменить обязанностью оставить понятный handoff.
  Предлагаю ограниченные сессии, право отклонить неподготовленную задачу, явный compute budget и отсутствие наказания за безопасную остановку.
  Это предложения для обсуждения: философские и экономические правила здесь не переписаны.
- **Первый успех.** Две маленькие полезные задачи, понятные критерии приёмки, доказанная выплата и восстановление после прерывания.
  Не количество issues, конкурентов или потраченных токенов.
- **Public.** Аудит текущих файлов и всей достижимой истории ещё не выполнен.
  Публикация требует проверки секретов, личных данных, identity exposure, лицензий и реальной branch protection.
